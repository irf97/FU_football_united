01 — ORIGIN

The original Football United app

Football United started as an amateur-football matchmaking product: find players, fill a match, play, rate each other, carry a rank. It is a Phoenix LiveView / PostgreSQL application, built and runnable today.

  • Surfaces: /browse, /queue, /lobby, /match, /postmatch, /profile, password-gated /admin.
  • A soft-join → hard-lock commitment model with bail penalties (1 day >24h before kickoff, 1 week within 24h).
  • A deterministic, append-only rank ledger: idempotent finalize, disputes-as-amendments, decay, rated 8v8 + 7v7. Sub-positions are display-only — a test-locked invariant keeps them out of matchmaking.
  • Captain-guarded tactics, friends/groups, per-queue chat.

Status: Real · tested · runnable — 156 tests / 5 properties / 0 failures. Pre-launch blockers are documented, not hidden (real SMS gateway; admin credential out of source).

04 — WHAT THE PROTOCOL MODEL DOES

The trust & sync core

The kernel specifies how a signed claim about a player's rank travels by physical proximity and how truth is derived from witnesses — not from any server.

  • Identity — Ed25519 (RFC 8032); a 32-byte seed deterministically yields a keypair; address = SHA-256(pub) first 16 hex chars.
  • Canonical encoding — the exact bytes signed: "{match}|{player}|{delta_milli}", integer-milli delta, no float formatting (language-stable across runtimes).
  • Verify-or-drop ingest — an attestation not validly signed by its declared author is dropped entirely: never folded, stored, or relayed.
  • Witnessed rank — a player's rank is the median of their witnesses' views, self excluded. A lone forger is powerless; a colluding minority cannot move it; a majority can — this is the stated, documented limit, not a defect.
  • Friendless bootstrap — proximity over time promotes acquaintances to provisional witnesses, so the friendless are still recoverable (mitigated to ~90% at 10k in simulation, not 100%).
  • Wire framing & pipeline — a byte-exact, digest-checked frame; two nodes converge on a witnessed rank using only chunked, reassembled bytes.

Validated in deterministic simulation to 10,000 users (flat storage, ~100% witness delivery, NFC-feasible payloads). Simulation is not field deployment.

05 — WHAT CONFORMANCE VECTORS PROVE

And, just as importantly, what they do not

fu/conformance/vectors.json (spec fu-mesh-conformance, version 6) is a set of deterministic input→output pairs generated by running the reference — not hand-typed constants. Ed25519 is deterministic (RFC 8032), so the signature bytes are stable expected values.

They prove

  • Reproducibility: another implementation can be checked byte/value-exact, section by section.
  • Regression safety: a normative change must bump the version and the self-check refuses any mismatch.
  • Anti-circularity: an independent code path re-derives every value rather than echoing the generator.

They do not prove

  • That the protocol design is correct or secure — a faithfully reproduced flaw is still a flaw.
  • That any network, runtime, or radio works — none exists.

Precedence is explicit and ordered: prose < vectors.json < reference code.

06 — THE PYTHON SECOND IMPLEMENTATION

What it reproduced — and its honest scope

An independent Python implementation (implementations/python-conformance/) was written from the spec + vectors, with a vendored pure-Python RFC 8032 Ed25519 (a separate crypto stack from the reference's) and zero third-party dependencies.

Result: 31 / 31 vectors @ v6 — every section reproduced value/byte-exact, including the byte-exact wire frame and signatures from the independent crypto path.

The honest asterisk. Its author had prior exposure to paraphrases of the algorithm. Per the project's own contract this is a spec-sufficiency audit, not a clean-room independence proof. It raised the contract's quality; it did not certify external reproducibility. That distinction is stated, not glossed.

07 — AMBIGUITIES FOUND & FIXED

The audit did its job

Building an independent implementation surfaced four under-specifications invisible while the reference checked itself. All are now closed in the contract.

A spec-stability pass also fixed prose that could drift from the vectors (the [0..N] inclusive-range trap; "ascending-sorted" median; anti-drift test-count wording). Honestly remaining and explicitly out of current conformance scope: R1 (the delta_milli decimal-vs-binary64 domain on untested deltas) and R2 (Ed25519 verify-equation variant on adversarial signatures). These are the frontier — documented, not pretended-covered.
