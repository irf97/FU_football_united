The Solid Node,
in full.

Twenty-five operational layers resting on one conceptual kernel. This supersedes the earlier node sketch: it is the complete architecture for a Football United peer that boots itself, proves who it is, governs what it accepts, forgets on purpose, survives a venue with no human, and updates without a cloud.

Standing context

The Elixir/Phoenix codebase is the simulator, oracle and conformance suite. The intended runtime is Rust per the baseline (§02) — no runtime is built; this whole document is aspirational architecture. The trust/sync algorithm is the validated v3 mesh model (see redefinition/FU_END_TO_END.html §04 and the technical appendix). Two device classes throughout: phone clients (PWA projection) and solid nodes (this spec).

00 — The Canonical Kernel

Everything reduces to six primitives.

The IrfTek reduction: the system is not a pile of features, it is Object + Authority + Propagation + Projection + Anchor — and the piece that was always implicit, now promoted to first-class: Expiry. Every layer below is an implementation of one or more of these. If a layer can't be expressed in the kernel, it doesn't belong on the node.

PRIM · 1

Object

The atomic, immutable, content-addressed unit of state — an event/record. Everything that exists is an Object with a hash.

PRIM · 2

Authority

Who may assert an Object — Ed25519 signatures, persona/device keys, capability tokens, the witness rule. Trust = verifiable authorship.

PRIM · 3

Propagation

How Objects move — proximity gossip, subject-directed relay, replication scope. The v3 routing model lives here.

PRIM · 4

Projection

How Objects fold into a view — the PWA, the rank, the lobby. Read models; never authoritative themselves.

PRIM · 5

Anchor

What binds an Object to reality — proof-of-proximity (NFC), signed time, the witness median, content hashes. The grounding against forgery.

PRIM · 6 — NEW

Expiry

Every Object knows its own lifetime: TTL, acquaintance lapse, checkpoint compaction, revocation. The system is bounded and forgetful by design, not by accident.

Why Expiry is the keystone

The v3 result — flat O(network) storage, ~100% delivery — only holds because state expires: TTL eviction, acquaintance decay, checkpoint compaction. The earlier append-only model (v1) drowned precisely because nothing expired (the Scuttlebutt blow-up). Making Expiry a kernel primitive is the formal statement of what made the network actually scale. It is not a cleanup chore; it is load-bearing.

The orphan problem is now answered two ways

(1) Protocol: the acquaintance→provisional-witness fix is implemented & re-validated — orphan recoverability up to 90.5% @10k. (2) Topology: a venue node is an always-on witness for whoever shows up. Together these cover the gap; the honest residual (~10% at scale) is the tail that never accrues sustained acquaintances.

L1 — Bootstrap

From bare metal to a claimed node.

  • First-node install flow — flash → boot → self-test → derive node keypair → await admin claim.
  • Genesis seed package — a signed bundle of default schemas, root trust anchors, kernel config; the node refuses to run without a verified genesis.
  • Default schemas — the Object/event types the domain needs on day zero (queue, membership, rank event, attestation).
  • First admin / persona claim — an unclaimed node is inert; the first signed claim binds an operator persona and issues the local trust root.
  • Factory reset — wipe state & keys back to genesis, leaving hardware identity (L21) intact; an explicit, signed, irreversible action.

Kernel: Authority is established here; genesis is the first Anchor.

L2 — Provisioning

Enrolling devices & personas.

  • Device enrollment — a device presents hardware identity (L21); the node issues a scoped local certificate.
  • QR / NFC pairing — out-of-band channel carries the public key + a short-lived enrolment capability; NFC tap = proof-of-proximity, the strongest pairing.
  • Key generation — keys are generated on-device, never transmitted; only public material + signed CSR-equivalents move.
  • Role assignment — player / captain / operator / venue-node, expressed as capability tokens (L7), not ambient roles.
  • Local certificate issue — short-lived, renewable, revocable (L7 revocation lists).
L7 — Auth / Keys

Ed25519 all the way down.

ConceptDefinitionKernel
Device keyPer-hardware keypair, sealed (TPM where present)Authority
Persona keyThe human's portable identity; survives device loss via recovery (L6)Authority
Capability tokenSigned, scoped, expiring grant ("may act as captain of queue X until T")Authority + Expiry
Signed eventsEvery Object carries an Ed25519 signature; unverifiable = dropped, never relayedObject + Anchor
Revocation listsSigned, gossiped tombstones for compromised keys/tokens; bounded & expiringAuthority + Expiry

This is the self-sovereign identity the launch review flagged as missing — concretely specified.

L3 — Config management

Versioned, defaulted, reversible.

  • YAML configs with strict schema validation at load; an invalid config never takes effect.
  • Versioned manifests — each config is a signed Object; history is the lineage.
  • Schema migration — forward migrations are explicit, signed, and idempotent.
  • Safe defaults — every key has a conservative default; a missing key is never fatal.
  • Config rollback — revert to the last-good signed manifest, mirroring the A/B update story (L14).

Kernel: SQLite/IPFS = Object; checkpoints/snapshots = Expiry made durable; DuckDB = Projection (analytics is a read model).

L17 — Schema registry

Objects have governed types.

  • Semantic object types — every Object declares its type; the registry is the authority on shape.
  • Domain & event schemas — queue, membership, rank event, attestation, tactics — versioned independently.
  • Version lineage — schemas are signed Objects; their history is the migration graph.
  • Compatibility rules — readers accept N and N−1; unknown future schemas are quarantined, not crashed (ties to L24 poisoned-schema).
L6 — Backup / recovery

You can lose the box, not the persona.

  • Local encrypted export — age-encrypted state + persona key bundle.
  • USB & home-vault backup — offline media and a trusted home node as cold stores.
  • Persona restore — re-derive a persona on a new device from the encrypted bundle + recovery secret; rank is re-witnessed by the network, not trusted from the backup alone.
  • Node disaster restore — rootfs snapshot + WAL replay + genesis re-verify → a venue box rebuilt from cold media.
Honest

A restored persona's rank must be re-anchored by witnesses (Anchor primitive) — a backup cannot self-assert reputation, or it becomes a forgery vector.

L4 — Service discovery

Local-first, no cloud registry.

  • mDNS / Avahi + DNS-SD — zero-config same-LAN discovery (fu-node-<id>.local).
  • CoreDNS — tiny on-node resolver for stable internal names, upstream-independent.
  • Semantic node registry — nodes gossip a signed, expiring self-description (role, schemas, capacity); the registry is itself mesh state, not a server.
  • Node discovery — mDNS for first contact; libp2p for the wider relay mesh.
L11 — Time / clock

Ordering without a global clock.

  • Local NTP for wall-clock sanity; monotonic clocks for intervals (the match clock, TTLs).
  • Signed timestamps — time assertions are Anchored; an unsigned "when" is untrusted.
  • Drift tolerance — bounded skew accepted; events outside the window are quarantined (ties to L24 replay).
  • Event ordering rules — content-addressed causal ordering, not wall-clock ties; Expiry decisions use monotonic time, never a peer's claimed clock.
L8 — Policy engine

Authorisation is data, not code.

  • OPA / Cedar-style policy (Rust-native) — "may this signed action, by this capability, on this Object, be accepted?"
  • Action rules — domain guards as policy: only-captain-edits-tactics, locked-leave-incurs-penalty, sub-position-never-reaches-matchmaking. These move from scattered code to one auditable place.
  • Conflict rules — deterministic resolution for concurrent Objects (witness median, last-writer-by-causal-order).
  • Safety guardrails — hard refusals (minor mode, export/delete) the runtime cannot override.

Kernel: the policy engine is the executable form of Authority.

L9 — Sandboxing

Nothing untrusted runs unfenced.

Untrusted plugin isolation is the default posture: a plugin gets a typed Object stream and a capability, nothing else.

L10 — Rate limiting / abuse control

Cost & trust, not just throttles.

  • Gateway limits (Caddy/NGINX) and NATS limits on the local bus.
  • Peer scoring — libp2p gossip scoring; misbehaving peers are down-ranked and shunned.
  • Spam quarantine — suspect Objects held, not relayed, pending witness corroboration.
  • Proof-of-work (optional) — a cost on cheap actions when under flood.
  • Trust decay — reputation/acquaintance lapses without reinforcement (this is the Expiry primitive applied to trust — already in v3).

L22 — Legal / safety

Ownership is local by construction.

  • Local data ownership — a persona's data lives on their device; there is no central store to subpoena or breach.
  • Consent rules — proximity sharing is opt-in per encounter tier (stranger/acquaintance/friend), enforced by policy (L8).
  • Child / minor modes — a hard guardrail class: restricted discovery, no public projection.
  • Public / private domain boundary — Objects carry a visibility scope; Projection (L4 PWA) must honour it.
  • Export / delete controls — the persona can export everything (L6) and tombstone their data (an Expiry assertion the network honours).
Honest

P2P shifts the legal posture from "we hold your data safely" to "you hold your own data" — strong for privacy, but minor-protection, abuse recourse and lawful deletion across a gossip network are genuinely hard and unsolved at the policy layer. Flagged, not closed.

L18 — Plugin system

The domain is a set of signed modules.

  • Domain modules — matchmaking, ranking, tactics shipped as versioned WASM plugins, not baked into the kernel.
  • Signed plugins — only plugins with a verified manifest (cosign, §L7) load.
  • Permissioned execution — each plugin declares the Object types & capabilities it needs; the policy engine grants or refuses.
  • UI projection plugins — Projection surfaces are pluggable too; the PWA is one projection, not the only possible one.
L19 — Local AI ops

The robot's culture & voice — make it fun.

The job is now defined. Solid nodes are physical robots living at venues — there will be many of them, and they should have character. Local AI gives each node a personality and a voice: it greets the regulars, hypes the match, ribs the loser, narrates the lock-in countdown, has opinions about formations. Many robots, many personalities, one shared culture. Fun is a feature, not a side effect.

  • Persona registry — each node carries a signed persona profile (voice, temperament, catchphrases, local lore); personas are versioned Objects, swappable, and gossip a little so a city's robots feel like a crew, not clones.
  • Model registry + quantized models — small on-device speech/language models, signed, content-addressed, version-pinned; runs offline on appliance-class hardware.
  • Voice I/O — local wake/greet + TTS; speech never leaves the node (privacy by construction, §L22).
  • Prompt templates & local evals — personality is templated & versioned; evals gate a persona update before it ships to the fleet (L14).
  • Memory compaction — an Expiry application: a robot remembers regulars and recent banter within a bounded window, then forgets — it does not hoard a transcript of everyone forever.
  • Fallback rule engine — every AI path has a deterministic non-AI fallback (canned lines); a model failure makes the robot terse, never broken. The node never depends on cognition to function.
Guardrails still apply

The AI is still a fenced WASM-class plugin (L9) under policy (L8): no authority over Objects, capability-gated, bounded memory, deterministic fallback. It shapes experience, never truth — a robot's banter cannot move a rank or confirm a match. Minor-mode (L22) constrains voice/persona accordingly.

L12 — Power management

Survive the outage; sip when idle.

  • UPS / battery with state telemetry; brown-out → checkpoint & graceful shutdown before data loss.
  • Low-power modes & wake schedules for venue boxes that only matter on match nights.
  • Radio duty cycling — BLE/Wi-Fi-Aware scan/advertise on a schedule to balance discovery vs. battery.
  • Graceful shutdown — systemd stop hooks flush WAL, sign a clean-shutdown marker.
L13 — Hardware health

The body reports.

Temperature · disk wear (SMART) · battery cycles · radio signal quality · antenna status · hardware watchdog. All emitted as OTel signals (L15); thresholds raise events the admin console (L20) surfaces and the policy engine can act on (e.g., shed radio load when thermal).

L14 — Update pipeline

Signed, A/B, reversible, offline-capable.

  • Signed releases + firmware version registry — every image is a signed Object with lineage.
  • A/B updates + rollback — atomic slot switch; no health beat → bootloader reverts.
  • Staged rollout — canary ring over WireGuard; halt on OTel regression.
  • Offline update via USB — a venue with no uplink updates from signed media; signature, not connectivity, is the gate.

The PWA projection updates separately (IPFS / service-worker), per the two-class rule.

L20 — Admin console

The whole node, one page.

Local, WireGuard-only, read-mostly; every action a signed operation. Panels: node status · peer status · domain status · keys & capabilities · updates & slot · backups · logs · permissions/policy. This is Projection over operational Objects — the same kernel, a different view.

L21 — Manufacturing / fleet

Identity is born at the factory.

  • Device serials + hardware identity — sealed at manufacture (TPM/secure element where present).
  • Secure provisioning — factory injects only public trust anchors + a unique device key; no shared secrets across the fleet.
  • Factory test + firmware flashing — automated bring-up test, signed first image.
  • Certification profile — a node attests its build/profile; the network can require a minimum profile to grant venue-node Authority.
L16 — Testing

Adversarial by default.

  • Simulation harness + fake nodes — the existing Elixir mesh sims (v1→v3) are the conformance oracle; the Rust runtime must reproduce their invariants.
  • Radio chaos tests — drop, delay, partition, asymmetric links.
  • Conflict tests — concurrent Objects, witness disagreement, healed partitions.
  • Offline/online + hostile-peer tests — every L24 threat has a reproducing test.
L23 — Documentation

Five guides + the model.

Operator guide · developer guide · schema guide · recovery guide · hardware install guide — plus the threat model (L24) and this architecture. The existing doc family (fu-spec / fu-dashboard / fu-network-pitch and the end-to-end narrative at redefinition/FU_END_TO_END.html) is the application/spec corpus; this node spec is the operational corpus. Both trace to the kernel.

14 — Honest open notes

What's specified vs. what's still hard.

  • This is specification, not running code. 25 layers defined; the Rust runtime, real radios, and protocol-grade crypto are still the build. The sim proved the model; this proves the plan.
  • Expiry-as-primitive is the real contribution here — it formalises why v3 scaled. Adopt it as the invariant the Rust runtime is tested against (nothing unbounded, ever).
  • Legal/minor/deletion across a gossip mesh is unsolved at the policy layer (L22). Strong privacy posture, hard compliance edges. Do not claim closed.
  • Friendless bootstrap — now substantially closed in the model. The acquaintance→provisional-witness fix is implemented & re-validated in the sim: orphan recoverability 100% @100, 80.7% @1k, 90.5% @10k (storage/coverage/payload unchanged). Honest residual: ~10% of orphans at scale still never accrue ≥2 sustained acquaintances and remain unrecoverable — venue nodes (§01) cover most of that tail, but it is mitigated, not zero.
  • Local AI now has a defined job (L19): the robot's persona & voice — fenced, optional, fallback-backed, no authority over truth.
  • Decisions still needed: phone client (PWA vs native for radio/background), persona recovery UX, and the certification-profile threshold for granting venue-node Authority.
Bottom line

The node now has a complete architecture and a kernel that explains why each layer exists. The next real deliverables remain: close the friendless-bootstrap gap in the sim, add true signature/identity semantics to the model so it's a faithful protocol reference, then the Rust runtime against these invariants.
